## 6. Pitfalls and conventions worth knowing

- **Moderation model:** `moderationStatus` is separate from `isPublished`; invariant: published implies APPROVED. Edits to an approved listing are staged in `metadata.pendingChanges`; critical fields (name, address, city, state, type) unpublish the listing on submit, non-critical (description, photos) keep it live.
- **`Unit.amenities` is a nullable `text[]` with no DB default.** Prisma `has`/`every` filters misbehave on NULL: use SQL with `COALESCE(amenities,'{}'::text[])`.
- **Invoices:** `invoiceNumber` is DB-generated (never set it in code). One live MAINTENANCE invoice per job (409 otherwise; cancel to resubmit). Vendor invoice amounts include 7.5% VAT that is not in the description lines.
- **Roles:** `canManageProperty(session, property)` (ADMIN or the property's manager/landlord) gates most mutations. Tenant dashboard money counts maintenance invoices on the tenant's own requests as owed (pre-existing behaviour; vendor bills are paid by the manager).
- **Routes that do not exist** (do not link to them): `/dashboard/leases`. Tenant lease signing happens on `/dashboard`; the manager's lease console is `/dashboard/tenants/[leaseId]`.
- **Time zone:** viewing times are Lagos time by design; everything else uses UTC or the viewer's local time.
- A `Monitor` on a log that already holds an old `EXIT` line fires immediately: delete the old log first. Foreground `sleep` is blocked: use `until grep -q ...; do sleep N; done` or the Monitor tool.
- The Claude Code permission classifier blocked `git checkout -B <branch> origin/dev`; create branches from an up-to-date local `dev` instead.
- Public pages should never show private units or unapproved listings; keep the regression tests in `tests/api/properties.test.ts` green (57 tests).
